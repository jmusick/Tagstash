# Tagstash marketing SEO and AI discovery audit

Audited October 7, 2026 using the seo-audit and ai-seo skills, with the schema skill
for structured-data changes. Scope: the homepage, the new Features page, their
rendering and metadata, routing, sitemap, robots.txt, llms.txt, and feature demos.

## Outcome

The strongest improvement was fixing an indexing blocker before deployment.
The Vite development server displayed Features correctly, but the Cloudflare Pages
middleware treated its production HTML as an unknown page and returned 404 with
`X-Robots-Tag: noindex`. This is fixed and verified through Wrangler Pages.

The homepage and Features page now provide readable product information and
matching page-specific schema in initial HTML. All 13 animation walkthroughs are
available as text without requiring a crawler to select alternate clips.

These are crawlability and clarity improvements. They are not evidence of better
rankings, more organic traffic, or more AI citations. Search Console, Bing Webmaster
Tools, field performance metrics, backlink data, and repeated AI-query measurements
were not available for this audit. No numeric SEO or agent-readiness score is claimed.

## What already works

- The homepage serves meaningful marketing copy and pricing through a Pages Function.
- Features is generated from the same React view used by visitors, not a separate bot-only page.
- Both marketing pages have one H1, descriptions, canonical URLs, and social metadata.
- Homepage links make Features discoverable, and its canonical URL is in the sitemap.
- robots.txt allows public marketing pages. Its existing private-route exclusions remain intact.
- Official Chrome and Firefox listings, the publisher link, support, and privacy information provide verifiable product context.
- Demonstrations use real local app states; their text walkthroughs describe the actual controls.
- Videos load on visibility, pause offscreen, support explicit pause, and respect reduced-motion preferences.
- Pricing is available in initial homepage HTML and in llms.txt; it is not locked behind login or video playback.

## Structured-data and AI-search limits

The new schema describes visible page content. No ratings, testimonials, customer
counts, awards, performance claims, or fabricated statistics were added.

FAQ markup is semantic context, not a promise of FAQ snippets for this SaaS site.
Google restricts FAQ rich results primarily to authoritative government and health
sites. The existing SoftwareApplication data is useful descriptive markup; without
genuine qualifying review/rating data, do not promise the software-app rich result.

The short clips illustrate features on a marketing page. They are not dedicated
video watch pages, so this audit does not claim video-search eligibility. Alternate
clips may still require a visitor to select a demo; their full text is independently
readable. No unnecessary VideoObject markup was added.

Google does not require special AI files or special schema to appear in its AI
features. Maintaining llms.txt can help systems that choose to read it, but it is
not a Google ranking factor. No citation lift from that file or from schema is assumed.

Cloudflare dashboard bot rules and verified crawler requests were not inspected.
The robots file alone cannot prove that every AI discovery crawler can pass the WAF.
Existing training-crawler policy was not changed as part of this marketing audit.

## Validation

1. `npm run build` successfully prerenders `dist/features.html`.
2. Changed application, content, utility, script, and Function files pass targeted ESLint.
3. Wrangler Pages returns 200 for `/features`, with no noindex header, one H1,
   full feature copy, all walkthroughs, and the expected canonical URL.
4. `/features/` and `/features.html` return 308 redirects to `/features`.
5. An unknown route remains a 404 with `X-Robots-Tag: noindex`.
6. Sitemap and robots.txt are accessible, and the sitemap includes Features.
7. Rendered-browser inspection confirms the initial homepage schema types, then
   verifies the correct Features schema and FAQ answers after React navigation.
8. A middleware regression test covers the public page, unknown-page 404s,
   redirects, and API response preservation.

At audit time, live `https://tagsta.sh/features` returned 404 because these local
changes have not been deployed. The fixes were validated locally against the
Cloudflare Pages serving model, not claimed as already live.

## Follow-up after deployment

1. Inspect `/features` in Search Console. Confirm the live 200 response, rendered
   content, indexability, and Google-selected canonical; request indexing and
   confirm the sitemap submission.
2. Run Rich Results Test and Schema.org Validator on the live URL. Eligibility
   warnings are distinct from malformed JSON or page-content mismatches.
3. Check field Core Web Vitals when enough traffic is available. Initial media
   loading is controlled, but no LCP/INP/CLS improvement was measured here.
4. Use Search Console queries and impressions to decide the next content topic.
   Candidate intents include “tag-based bookmark manager,” “bookmark manager with
   multiple tags,” “share bookmarks publicly,” and “Tagstash bookmark export.”
5. For AI visibility, test a small set of meaningful product questions repeatedly
   across the relevant engines and record citation/mention rates with sample sizes.
   One generated answer or a `site:` query is not a reliable visibility baseline.
6. Consider focused how-to guides based on actual demand: combining tags, moving
   from browser bookmarks, or embedding a public collection. Avoid thin comparison
   pages, unsupported “best” claims, and invented customer evidence.
